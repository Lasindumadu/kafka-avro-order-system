Section 1

System Overview

This system simulates a real-time order processing pipeline using Apache Kafka. Orders are produced, serialized with Apache Avro, consumed, validated, and aggregated — with full retry and dead letter queue support.

Section 2

Prerequisites & Installation

1Install Docker Desktop

Docker Desktop runs Apache Kafka as a container — no manual Kafka installation needed.

Download: Visit https://www.docker.com/products/docker-desktop, download the Windows installer, and run it. Restart your computer when prompted.

After installation, open Docker Desktop from the Start menu and wait until it shows "Docker Desktop is running" in the system tray.

Verify Docker is working:

docker --version
# Expected output: Docker version 24.x.x, ...

2Install Python 3.8+

Python is required to run the producer and consumer scripts.

Download: Visit https://www.python.org/downloads/ and download the latest Python 3.x installer. During installation, check "Add Python to PATH".

Verify Python is working:

python --version
# Expected output: Python 3.x.x

3Install Python Dependencies

Open PowerShell, navigate to the project folder, and run:

cd "C:\Users\Admin\Desktop\Big data takehome"
pip install -r requirements.txt

This installs the following packages:

PackageVersionPurpose
confluent-kafka2.3.0Kafka producer and consumer client
fastavro1.9.4Avro serialization and deserialization
flask3.0.3Web server for the dashboard
flask-socketio5.3.6Real-time WebSocket communication
Tip: If you get a permissions error, try running PowerShell as Administrator, or add --user to the pip command.

4Clone or Open the Project

The project is hosted on GitHub. If you need to re-download it:

git clone https://github.com/Lasindumadu/kafka-avro-order-system.git
cd kafka-avro-order-system

Or simply navigate to the existing project folder:

cd "C:\Users\Admin\Desktop\Big data takehome"
Section 3

Running the System

Important: Always start Kafka first (Step 1) and wait ~15 seconds before running the producer or consumer. Kafka must be fully ready to accept connections.

1Start Kafka (Terminal 1)

Open PowerShell in the project folder and run:

docker-compose up -d

Expected output:

PowerShell — Terminal 1
[+] Running 2/2
 ✔ Network kafka-avro-order-system_default  Created
 ✔ Container kafka                         Started

Verify Kafka is running:

docker-compose ps
# Should show: kafka   Up
Wait 15 seconds after this step before proceeding. Kafka needs time to fully initialize its internal topics and become ready for connections.

2Start the Dashboard (Terminal 2)

Open a new PowerShell window in the project folder and run:

python app.py

Expected output:

PowerShell — Terminal 2 (Dashboard)
[Dashboard] http://localhost:5000

Open your browser and navigate to http://localhost:5000 to view the live dashboard.

3Start the Producer (Terminal 3)

Open a third PowerShell window in the project folder and run:

python producer.py

Expected output:

PowerShell — Terminal 3 (Producer)
[Producer] Publishing to 'orders'. Press Ctrl+C to stop.

[Producer] Sent → orderId=1000, product=Item3, price=$243.50
[Producer] Sent → orderId=1001, product=Item1, price=$87.20
[Producer] Sent → orderId=1002, product=Item4, price=$0.00 [INVALID]
[Producer] Sent → orderId=1003, product=Item2, price=$341.00
Note: The producer sends one order per second. Approximately 5% of orders are intentionally invalid (price = $0.00) to demonstrate the retry and DLQ flow. These are marked [INVALID] in the producer output.

Retry Logic Explained

When a message fails validation or hits a transient processing error:

AttemptWait Before RetryFormula
Retry 12 seconds2 × 2⁰ = 2s
Retry 24 seconds2 × 2¹ = 4s
Retry 38 seconds2 × 2² = 8s
After Retry 3—Message forwarded to DLQ

Dead Letter Queue (DLQ) — Two Paths

TriggerPathTopic
Order with price = 0.0 Retry 1 → Retry 2 → Retry 3 → DLQ orders.dlq
Transient processing error (15% rate) Retry until exhausted → DLQ orders.dlq
Non-retryable (e.g. bad Avro bytes) Straight to DLQ (no retries) orders.dlq
DLQ messages include metadata. Each message forwarded to orders.dlq carries a Kafka header named failure_reason explaining why it failed.

Shutdown

Stopping the System

Stop the producer and consumer by pressing Ctrl+C in their respective terminals.

Then stop and remove the Kafka container:

# Stop containers (keeps data)
docker-compose down

# Stop AND delete all Kafka data (clean slate for next run)
docker-compose down -v
Note: Using docker-compose down -v deletes all Kafka topic data. The next time you start, the consumer will read from offset 0 again. Use docker-compose down (without -v) to preserve data between runs.
  • Kafka starts with a single Docker container (no Zookeeper)
  • Producer serializes every message using Apache Avro
  • Consumer deserializes and validates each message
  • Running average updates after every successful order
  • Retry logic fires with exponential back-off (2s → 4s → 8s)
  • Failed messages are forwarded to the DLQ with a failure reason header
  • Real-time dashboard reflects all events via WebSocket
